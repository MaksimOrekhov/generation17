# content/ — тексты игры

Здесь живут сюжеты и моменты, написанные как данные. Код игры не нужно менять: достаточно добавить JSON-файл и запустить проверку.

```
content/
  STYLE.md          голос, мир, правила русского текста — прочитать первым
  README.md         формат файлов (этот файл)
  storylets/*.json  сюжеты: год останавливается, игрок выбирает (массив)
  moments/*.json    моменты: маленькая возможность в течение года (массив)
```

После правок:

```bash
npm run content
```

Команда проверяет все файлы и, если ошибок нет, обновляет `src/content/bundle.json` (его читает игра). Коммитьте файлы в `content/` вместе с обновлённым `bundle.json`. `npm run content:check` только проверяет и ничего не пишет; `npm test` тоже проверяет содержимое.

**Нельзя** менять `src/` (кроме `src/content/bundle.json`, он генерируется). Новый вид условия или эффекта, стат, категория, линия `arc` или подстановка — это просьба к Claude, а не правка вручную.

## Файл — это JSON-массив

Имя файла произвольное: `childhood-02.json`, `adult-signal.json`. В один файл удобно складывать 5–20 записей одной темы. Идентификаторы (`id`) уникальны среди **всей** игры: латиница, строчные, через дефис. Моменты начинаются с `m-`.

## Формы по роду

В тексте (`body`, `text`, `result`, `label`, `memory`) можно писать формы `{{кто:мужская|женская}}`: `Заступил{{hero:ся|ась}}`, `{{friend:Он|Она}}`, `{{child:сын|дочь}}`. Кто: `hero`, `parent`, `child`, `sibling`, `friend`, `neighbor`, `mentor`. Подробные правила и примеры: [STYLE.md](STYLE.md#род-герой-ребёнок-и-другие-люди).

## Сюжет

```json
{
  "id": "tin-whistle",
  "category": "Детство",
  "title": "Жестяная дудочка",
  "body": "Текст ситуации. {{neighbor}} …",
  "min": 6, "max": 10, "weight": 3,
  "requires": { "flagNot": ["tinWhistle"] },
  "choices": [
    {
      "text": "Дудеть в коридоре",
      "hint": "Радость ↑ · Сосед ↓",
      "result": "Что случилось сразу.",
      "effects": {
        "stats": { "morale": 3 },
        "bonds": { "neighbor": -3 },
        "flags": { "tinWhistle": "played", "tinWhistleAge": "@age" }
      }
    }
  ]
}
```

| Поле | Значение |
|---|---|
| `id` | уникальный идентификатор |
| `category` | Детство, Юность, Семья, Отношения, Профессия, Общество, Корабль, Повседневность, Личное, Здоровье, Тайна, Поздняя жизнь, Наследие, Последствие |
| `title` | 3–40 символов |
| `body` | 60–420 символов, цель 130–280 |
| `min`, `max` | возраст героя (0–95), в котором сюжет может выпасть |
| `weight` | 1–8: вероятность выбора среди подходящих сюжетов **той же очерёдности** (`priority`) |
| `priority` | необязательно: `followup` — продолжение начатой линии (идёт раньше обычных сюжетов, но уважает интервал между решениями и бюджет напряжения); `critical` — обещанное по сроку (не ждёт напряжения и «тихого года», но не раньше минимального интервала). Обязателен `requires` с `flag`, `flagIs`, `since` или `until`. Если у сюжета есть `until`, то в последний год окна он выходит вне очереди |
| `weird` | необязательно: `1` — только в атмосфере «тайны» и тревожной, `2` — только в тревожной |
| `arc`, `fork` | линия сюжета; только существующие, новые согласуйте с Claude |
| `requires` | условия показа (ниже); без поля — показывается всегда в своём возрасте |
| `choices` | 2–4 выбора |

Выбор: `text` (до 40), `hint` (до 50), `result` (20–260, цель 60–160), `effects`, необязательно `check`.

`check`: проверка навыка перед исходом.

```json
"check": {
  "skill": "social", "difficulty": 12,
  "successText": "…", "failureText": "…",
  "success": { "stats": { "reputation": 3 } },
  "failure": { "stats": { "stress": 3 } }
}
```

`skill`: engineering, medicine, ecology, social. `difficulty`: 5–35 (чем больше, тем труднее; обычно 6–30). При `check` поле `effects` выбора тоже обязательно (общая часть, может быть `{}`).

## Момент

```json
{
  "id": "m-whistle-echo",
  "spot": "door",
  "title": "Знакомый звук",
  "text": "Одно наблюдение.",
  "min": 8, "max": 20, "weight": 2,
  "cooldown": null,
  "needs": ["parent"],
  "requires": { "flagIs": { "tinWhistle": ["played", "tuned"] } },
  "accept": { "label": "Пойти на звук", "result": "…", "effects": { "stats": { "morale": 2 } } },
  "skip": { "label": "Пройти мимо" }
}
```

| Поле | Значение |
|---|---|
| `spot` | `window`, `door`, `terminal`, `parent`, `table`, `plant` |
| `text` | 30–260, цель 60–130 |
| `weight` | 1–5 |
| `cooldown` | целое 1–12 (через сколько лет можно повторить) или `null` — один раз за жизнь |
| `needs` | необязательно: кто должен быть жив и известен (`parent`, `friend`, `neighbor`, `mentor`, `sibling`, `child`). Обязательно, если в тексте метка этого человека |
| `accept` | то, что происходит при отклике: `label`, `result`, `effects` |
| `skip` | отказ: `label`, необязательно `effects` |

## effects

Все поля необязательны; в `choices[].effects` и `accept.effects` сам объект обязателен (можно `{}`).

| Поле | Ключи | Предел за одно событие |
|---|---|---|
| `stats` | health, morale, stress, knowledge, bonds, reputation | ±10 (предупреждение выше ±8) |
| `skills` | engineering, medicine, ecology, social | ±4 |
| `ship` | air, food, cohesion, hull | ±6 |
| `bonds` | parent, parent2, sibling, friend, neighbor, mentor, child | ±18 |
| `flags` | любое имя camelCase → строка, число или `true`/`false`; `"@age"` = текущий возраст героя | |
| `job` | Ученик, Техник, Медик, Агроном, Координатор, Без специальности, Переобучение | смена профессии, редко |
| `memory` | строка 10–140 символов; безличная или с формами по роду («Выбрал{{hero:|а}} дело.») | запись в «воспоминания» |
| `addPerson` | `"child"` | в жизни героя появляется ребёнок: имя игра выбирает сама, фамилия как у героя, возраст 0, связь 70. Повторно не добавляет. Дальше `child` можно использовать в `bonds`, `needs`, `alive` и как метку `{{child}}` |
| `moveTo` | `atrium`, `bio`, `engineering`, `clinic`, `lower` | герой переезжает в этот сектор: меняются «Сектор» в личном деле, вид каюты и фоновые строки. Сектор рождения остаётся в свидетельстве |
| `money` | целое число со знаком от −1500 до +1500 | расход или поступление кредитов; `0` не меняет финансовую историю |

Числа только целые.

### Деньги в решении (T6)

Например, `"effects": { "money": -400, "flags": { "helpPaid": true } }` списывает 400 кр одновременно с остальными эффектами. `"effects": { "money": 250 }` начисляет 250 кр. Цена показывается рядом с вариантом как «−400 кр.», поступление — как «+250 кр.». При балансе 300 кр платный вариант остаётся видимым, но выключен с причиной «Не хватает 100 кр.».

В каждом сюжете с расходом обязателен хотя бы один вариант без обязательного денежного списания: `effects: {}`, `money: 0` или поступление. Возможный возврат денег в `check.success` не делает предварительную оплату бесплатной. В `check.success` и `check.failure` отрицательные `money` запрещены; положительные награды допустимы и показываются как условные. Каждый отдельный эффект ограничен ±1500, поэтому основной эффект и награда проверки могут создавать две отдельные операции.

Движок, Pinia и интерфейс используют `canChoose(game, index)`. Проверка повторяется в момент выбора, включая клавиши 1–4. При отказе ничего не применяется: баланс, RNG, показатели, флаги, воспоминания, история и ожидающее решение сохраняются; пустой экран результата не открывается. При угрозе переполнения безопасных целых в балансе, итогах или номере операции выбор также отклоняется целиком. Проверяются оба возможных исхода навыка после основного денежного эффекта, до броска RNG.

Поступление записывается в общий финансовый журнал как `windfall` и увеличивает `totals.earned`; добровольная оплата — как `story-expense` и увеличивает `totals.spent`. `amount` в журнале всегда положительный, направление задаётся видом операции, `ref` и подпись указывают на сюжет. Это не покупка из `OFFERS`, отдельного журнала нет. Нулевой эффект не создаёт операцию. Журнал и итоги сохраняются при загрузке.

В моментах `accept.effects.money` и `skip.effects.money` могут быть только нулевыми или положительными. Они используют тот же финансовый механизм; `skip` применяется только при явном отказе. Истечение через `beat()`/`tick()` не применяет ни `accept`, ни `skip`, не начисляет и не списывает деньги. Отрицательные расходы в моментах пока не поддерживаются.

## requires — условия показа

Все указанные поля должны выполняться одновременно.

| Поле | Пример | Смысл |
|---|---|---|
| `flag` | `["a", "b"]` | все эти флаги заданы |
| `flagNot` | `["a"]` | ни один из флагов не задан |
| `flagIs` | `{ "nursery": "brave" }` или `{ "x": ["a", "b"] }` | флаг равен значению (или одному из списка) |
| `flagNotIs` | `{ "friendState": "estranged" }` | флаг не равен значению (ни одному из списка); незаданный флаг подходит |
| `since` | `{ "tinWhistleAge": 3 }` | флаг-возраст (записанный через `"@age"`) был не менее 3 лет назад |
| `until` | `{ "familyChildAge": 6 }` | флаг-возраст был не более 6 лет назад (вместе с `since` задаёт окно, например «от 4 до 10 лет после») |
| `personAge` | `{ "parent": { "min": 75 } }` | возраст человека в границах `min`/`max`; человек должен быть в списке людей героя (для `child` — уже появиться), но может быть и мёртв. Момент с `needs: ["child"]` обязан задать `personAge.child.max`: сцена должна подходить возрасту ребёнка |
| `job` | `["Медик"]` | профессия героя из списка |
| `alive` | `["parent"]` | эти люди живы (в том числе `child`: ребёнок уже появился и жив) |
| `present` | `["child"]` | эти люди живы и уже появились в жизни героя. Вместе с `personAge` даёт «возраст + присутствие»: `personAge` сам не проверяет, жив ли человек |
| `sector` | `["bio"]` | герой сейчас живёт в одном из этих секторов |
| `sectorNot` | `["bio"]` | герой сейчас живёт не в этих секторах |
| `stat` | `{ "stress": { "min": 60 } }` | показатель в границах |
| `money` | `{ "min": 1500, "max": 4000 }` | текущий `economy.balance`, границы включительно |
| `work` | `["working", "sick"]` | статус занятости, а не профессия: `child`, `trainee`, `working`, `between`, `sick`, `retired` |
| `grade` | `{ "min": 2 }` | текущий тарифный разряд 1–4 |
| `housing` | `{ "min": 1, "max": 2 }` | текущее жильё H0–H2 |
| `owns` | `["own-cabin", "dome-pass", "visit-sector-bio"]` | все ключи зарегистрированы в `economy.owned` или активных `economy.services` |
| `ownsNot` | `["dome-pass"]` | ни один ключ не зарегистрирован в этих коллекциях |
| `reserveYears` | `{ "min": 3, "max": 10.5 }` | баланс / текущие годовые обязательства; точное отношение, без округления |

В новых числовых условиях нужна хотя бы одна граница `min` или `max`; обе включительны, `min <= max`. Неизвестные вложенные ключи запрещены. `money` — неотрицательное безопасное целое до `Number.MAX_SAFE_INTEGER`; `grade` и `housing` — целые в указанных диапазонах. Границы `reserveYears` — от 0 до 1000 лет с шагом 0,1; сам вычисленный резерв не округляется к десятым.

`annualObligationsOf()` использует те же нужды, аренду и стоимость подключённых услуг, что годовой расчёт: учитываются ребёнок, профессиональные льготы и текущее закрытие услуг. Это годовой размер **текущих** обязательств, без разовых взносов и без отмены непосильных услуг/понижения жилья ради уменьшения знаменателя. Это не прогноз следующего возраста: в частности, последний год содержания ребёнка и разовая отсрочка первой аренды не заменяют текущую годовую ставку. Если обязательства нулевые, `reserveYearsOf()` возвращает `null` как признак неограниченного покрытия: любая конечная граница `min` выполняется, любая `max` — нет, в том числе при нулевом балансе. Деления на ноль, `NaN` и `Infinity` не создаются.

`owns: ["own-cabin"]` означает исторически зарегистрированное приобретение: после экономической потери H1 этот факт остаётся. Для нынешних жилищных условий используйте `housing`. Отменённый купол перестаёт удовлетворять `owns`, а оплаченный ранее курс не становится собственностью лишь из-за `lastBought`. Валидатор принимает известные ID каталога и `visit-sector-<id>` только для существующих секторов: `atrium`, `bio`, `engineering`, `clinic`, `lower`. Коллекция `lastBought` не участвует в `owns`.

Пример сочетания условий (только синтаксис, не новый сюжет T7):

```json
{
  "money": { "min": 1500 },
  "work": ["working"],
  "grade": { "min": 2 },
  "housing": { "min": 1 },
  "reserveYears": { "min": 3 }
}
```

Эти поля объединяются логическим И с прежними `flag`, `job`, `alive`, `stat` и другими условиями. Проверка чистая и не расходует RNG. Без новых полей прежняя достижимость сюжетов сохраняется.

Флаг можно читать только если какой-то сюжет (в коде или в ваших файлах) его ставит. Иначе проверка выдаст ошибку.

## Что проверяет `npm run content`

Ошибки (блокируют сборку): неверный JSON, неизвестные поля, дубли `id`, длины текстов, неизвестные категории, стат, навыки, подстановки, люди; метка человека без гарантии в `body`/`needs`; чтение несуществующего флага; число выборов; слишком большие эффекты.
Предупреждения (не блокируют, но их стоит убрать): длинный текст, сильный эффект, латиница, возможная форма рода в прошедшем времени.
