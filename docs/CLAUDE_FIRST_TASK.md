Не нужен Opus/Fable на регулярной основе. Если используешь Claude Code, можно держать Sonnet основной моделью и делегировать небольшие изолированные задачи Haiku. ## Цель
Не переписывая игру с нуля, превратить текущий vertical slice в надёжную и интересную основу симулятора одной жизни на корабле поколений. Сохранить задумку: минималистичный текстовый UI, человек в центре повествования, мир живёт независимо, «Пилигрим» летит 340 лет, старт — на 190-м году миссии.

## Последовательность действий
1. Запусти `npm install`, `npm run build`, `npm test`; сообщи, какие ошибки существовали до правок. Исправь замеченные проблемы компиляции или поведения, но не замалчивай их.
2. Проведи **короткое инженерно-геймдизайнерское ревью**. Укажи конкретные дефекты, сценарии воспроизведения и приоритет. Особенно проверь: состояние RNG, детерминизм, сохранение, pause-on-choice, своевременное применение NPC смертности, дубли событий, последующее исполнение следствий.
3. Исправь фундаментальные ошибки, не меняя структуру без веской причины. Укрепи вычисление игрового года и выбор событий; не запускай побочные эффекты внутри Vue-компонента, если они относятся к симуляции.
4. Углуби **две** сюжетные дуги, не двадцать поверхностных:
   - «Незарегистрированная трещина»: отдельно обработай официальный рапорт, удачный ремонт, неудачный ремонт, молчание; последствия через 4–15 лет; роль архивов, репутация, безопасность.
   - «Дружба детства»: школьное обвинение → изменения доверия → встреча во взрослом возрасте; варианты должны различаться и по тону, и по доступным решениям.
   Важно: последствия не должны предсказуемо давать всегда один «правильный» выбор.
5. Проведи *1 000 детерминированных прогонов* с несколькими стратегиями: первый вариант, последний вариант, разные случайные варианты, приоритет отдыха, приоритет учёбы, приоритет отношений. Отчёт: средний возраст, медиана, 10–90 перцентили, количество решений, среднее число отложенных последствий, список недостижимых событий, аварии логики. Создай тест/скрипт в репозитории, а не описывай вычисления на словах.
6. Отшлифуй UI без больших иллюстраций: ясность текста, статусы, визуальная иерархия, адаптивность. Без новой библиотеки компонентов, UI-фреймворка или CSS-движка, пока нет необходимости. Сохраняй плотную информативность.
7. Избегай внешних AI API во время игры. Не вводи бэкенд, регистрацию, платежи, многопользовательский режим или редактор событий в этой задаче.

## Условия приёмки
- `npm run build` и `npm test` без ошибок.
- Детерминизм: одинаковый seed и последовательность решений дают идентичные журнал, состояние и итог.
- Пауза: возраст и RNG не меняются, когда игра приостановлена или ждёт решения.
- Ни один год и ни одно решение не перепрыгивается на 8× или при быстром переходе до следующего события.
- Сохранение/загрузка: состояние восстанавливается без двойного применения последнего события, включая активное решение и накопленные флаги.
- Никакое событие не говорит об умершем NPC как о живом. При невозможности — заменяй кандидата или блокируй событие.
- Хотя бы две упомянутые линии имеют действительно разные последствия по веткам, видимые позднее в хронике.
- Отчёт автомоделирования содержит фактические числа и воспроизводимую команду запуска.
- Все изменения локализованы по назначению; не меняй внешнюю идею игры без обсуждения в итоговом отчёте.

## Ограничения
- Vue 3 Composition API, `<script setup lang="ts">`, TypeScript strict.
- Код без `;` в конце строк, где это возможно.
- Следуй существующему дизайну; избегай картинок и громоздких компонентных библиотек.
- Не копируй код, тексты, графику или точную вёрстку 1 in 8 Billion.
- Короткие ясные коммиты по логическим частям, без merge в main и без push без разрешения владельца репозитория.
- Если видишь более удачное решение, предложи или реализуй **маленькое обоснованное улучшение**, не ограничивайся механическим следованием прототипу.

## Ожидаемый отчёт
- Что найдено/исправлено, перечень файлов и тестов.
- Метрики серийных симуляций и 2–3 примера причинно-следственных цепочек.
- Уязвимости геймдизайна: повторы, отсутствие реакции на выбор, слишком много/мало сюжетов, скучные промежутки.
- 3 рекомендуемые следующие задачи **с обоснованием приоритета**, без больших рефакторингов ради рефакторинга.
