# Content Language v2 — схема и контракт

Проектирование перед реализацией, 29.10.2026. База: `c381176`, аналитическая ветка уже в main.

## Выбранная схема

Строки остаются строками. Поля `bodyVariants`, `resultVariants`, `textVariants`
содержат упорядоченный массив `{ requires, text }`. Первый подходящий элемент
заменяет исходную строку; иначе используется исходная строка. Компилятор один раз
строит чистые предикаты. Проверки и подбор текста не используют RNG.

`choices[].id` — обязательный смысловой ключ нового JSON. Старые JSON-пакеты
перечисляются в явном списке совместимости; старый TypeScript может не иметь ID.
Позиция никогда не выдаётся за стабильный ID. Решения без ID записываются с
`choice: "legacy-index:N"` и `legacy: true`; на них запрещены ссылки `chose`. Для новых вызывающих сторон есть `decideById(g, choiceId)`.

`GameState.decisions` хранит `{ id, choice, age, epilogue?, legacy? }`.
Успешное решение добавляет одну запись после всех операций; эпилог подставляется
и фиксируется до эффектов. Старые сохранения получают пустой журнал, без
восстановления решений из флагов или seen. Неизвестные исторические ID сохраняются.

`choices[].requires` использует общий язык условий. Биографически невозможные
ответы скрываются. Деньги и личное время проверяются прежними доменными правилами:
вариант виден с причиной блокировки. UI хранит исходный индекс, нумерует видимые
ответы заново; store предоставляет отдельный `chooseVisible` для клавиатуры.
Новый JSON обязан иметь безусловный бесплатный выход. Повреждённый старый pending
без доступного выхода снимается с записью в хронике, без выдуманного решения.

## Условия

Все поля объекта соединены И. `any` — непустой массив альтернатив ИЛИ;
максимальная глубина вложенности 8. Сохраняются все условия T6–T9.

- `seen`, `notSeen`: ID показанных сюжетов из `seen` (показ ≠ принятие решения).
- `chose: { "story-id": ["choice-id"] }`: есть успешная запись с этим ID.
- `decisionYears: { "story-id": { min?, max? } }`: годы с решения, границы включены;
  вместе с `chose` проверяет ту же запись. Нет записи — false.
- `bond`, `skill`, `ship`: карты ID → `{ min?, max? }`.
- `birthWealth: { min?, max? }`, `trait: ["Любознательный"]`.
- `alive`: человек существует и жив (включая ещё не появившегося).
- `present`: жив и уже появился (`since <= age`).
- `dead`: существует, появился и умер.
- `absent`: противоположность present; включает никогда не появившегося и умершего.
- `exists`: человек существует и уже появился, в том числе умерший. Совместно с
  absent/alive отличает отсутствие от смерти; отсутствующий ID не является dead.

Для текстов исходные обстоятельства вычисляются до эффектов: body при показе,
result/check/epilogue перед выполнением решения, момент перед откликом.
Результат не перечитывает собственные изменённые флаги. Фактическая развязка
проверки навыка по-прежнему выбирается её единственным прежним RNG-броском.

## Регистрация и совместимость

`content/lines.json`: массив `{ id, title, start }`, где start — ID начала с
`fork: true`; продолжения имеют тот же arc. `content/categories.json`: массив
`{ id, title }`, где id — ключ, title — подпись в UI (совместимо с текущим директором).
Реестр объединяется с кодовым каталогом при валидации. Развилки остаются прежними
`forks`; в сохранении уже есть снимки заголовков и ответов, поэтому удаление реестра
не стирает прошлое. Никакой второй системы линий нет.

Метаданные сюжета: `tone` = calm/warm/tense/crisis (выше старого TONE_OVERRIDES),
`tags` = массив kebab-case ID, `group` = kebab-case ID. Группы пока только данные.
Weight — вероятность среди равных приоритетов; followup/critical — очерёдность,
а не большой вес. При миграции старые веса сохраняются явно.

Единый реестр меток людей: parent, parent2, sibling, friend, neighbor, mentor,
child. Базовая метка в body сохраняет прежнюю неявную охрану present. Условный
текст охраняется только собственным requires и активным вариантом, а не объединением
всех альтернатив. Упоминание умершего возможно с явным dead/exists, имя берётся
из сохранённого человека. Эффект addPerson позволяет упоминать нового ребёнка
в результате после его появления; исходные условия всё равно оцениваются до эффекта.

## Границы

Нет JS, выражений, циклов, произвольных эффектов, новых NPC или механик директора.
Сложные кодовые истории с вычисляемыми эффектами остаются в TypeScript. Флаги,
seen, forks, history, memories, экономика и личное время сохраняются. Новым авторам:
не менять смысл существующего choice ID; регистрировать arc до использования;
добавлять бесплатный выход и тест трёх разных биографий.


## Точная запись новых полей

```typescript
// Дополняют прежние строковые поля, не заменяют их.
interface JsonTextVariant { requires: Requires; text: string }
// Storylet: bodyVariants?: JsonTextVariant[], tone?: Tone, tags?: string[], group?: string
// Choice: id: string, requires?: Requires, resultVariants?: JsonTextVariant[], epilogue?: string
// Choice.check: successVariants?: JsonTextVariant[], failureVariants?: JsonTextVariant[]
// Moment: textVariants?: JsonTextVariant[]; accept.resultVariants?: JsonTextVariant[]
```

В массиве альтернатив 1–32 записи, строка каждой проходит те же ограничения длины,
подстановок и охраны людей, что базовое поле. Ветка any содержит 1–32 объекта;
максимум 8 уровней вложенности. Включительные диапазоны новых числовых условий:
навык/связь/корабль 0–100, birthWealth 1–5, decisionYears 0–120, целые числа.
Все операторы из старого README сохраняют прежнюю семантику.

`seen` означает показ, поэтому включает ожидающее событие до ответа. `chose`
означает успешно исполненный выбор; запись появляется после эффектов и покупки,
а условия результата оцениваются до неё. `decisionYears` без chose может читать
возраст явно помеченного legacy-решения: возраст надёжен, смысл позиции — нет.
При совместном использовании с chose проверяются выбор и возраст одной записи.
Запись решения не вызывает случайность; check продолжает использовать прежний
единственный бросок навыка.

`until` и decisionYears.max компилируются в expiresIn для существующего механизма
дедлайнов директора. Для any берётся самое позднее окно среди активных альтернатив,
для остальных полей — минимум ограничений И; возрастное max события остаётся
внешней границей. Это не добавляет новых вероятностных правил.

В старом контенте, перечисленном в compatibility.json, отсутствие choice ID
разрешено явно. Новым событиям и новым линиям нужны смысловые ID. Исходный порядок
вариантов «Соседа» привязан к этим ID в политиках ботов: перестановка массива не
меняет выбранный смысл. В обычной игре между TS и JSON изменяется порядок каталога,
поэтому полные жизни могут разойтись законно; сравнение миграции идёт на одинаковых
состояниях и с неизменяемым предмиграционным эталоном.

В нынешней модели нет отдельного переезда/ухода NPC: unavailable = ещё не появился
или умер. exists + absent отличает существовавшего человека от никогда не
появлявшегося, а dead уточняет смерть. Будущий этап «Люди как данные» сможет
расширить isKnown состоянием человека, не меняя синтаксис ссылок.

Эпилог описывает факт принятого решения, а не гарантированный успех навыка.
Фиксируются подставленные имена и род; через десятилетия они не пересчитываются.
Старым событиям эпилоги не выдумываются. Полная хроника этим этапом не создаётся.
