# Люди и отношения v2

## Личность, роли и состояние

`Person.id` — постоянная идентичность; исходные `friend`, `parent`, `child` и другие сохраняют свои исторические ID. `role` остаётся описанием человека, а `relationships.partnerId` и `formerPartnerIds` ссылаются на те же объекты. Таким образом, друг может быть и партнёром, без второй карточки. `bond` остаётся числом близости. Умершие люди и прежние отношения не удаляются.

Для старой линии любви флаги остаются источником истины, пока не создано явное `relationships`: подтверждённые стадии при `lovePath: confessed` разрешаются в друга; одного признания недостаточно. Совместная жизнь с другом при корректной старой стадии тоже является подтверждением, даже если старый `lovePath` отсутствует. Данные при чтении не дописываются и не придумываются. При явной модели старое начало доступно без текущего партнёра, в том числе после разрыва или утраты другого человека. Признание оставляет статус открытым; решение о совместной жизни связывает партнёрскую роль с тем же другом и сохраняет прежних партнёров. Расставание в старом продолжении сохраняет друга в истории, если отношения с ним были подтверждены.

Новый партнёр не заменяет действующего, а неразрешённое признание живому другу не допускает параллельного начала другой романтической линии. Продолжения совместной жизни требуют именно друга-партнёра при явной модели; историческая встреча после расставания остаётся доступной. Проверка применяется и к уже ожидающему выбору, если обстоятельства изменились. Если явный разрыв завершил отношения на неоднозначной стадии `open`, необязательный `relationships.friendLoveClosed` закрывает именно это продолжение; сам факт, что друг был бывшим партнёром ещё до начала старой линии, её не блокирует. Старые `lovePath`, `loveStage` и журнал решений не обнуляются. Сохранения без явной модели и замороженные последствия старых сцен остаются прежними.

Дополнительные поля `Person.state` необязательны: `sectorId`, `job`, `availability` (`available` или `distant`), `familyStatus` (`unknown`, `single`, `family`). `distant` исключает присутствие, но не означает смерть: `alive` и `exists` по-прежнему могут выполняться. Неизвестная старая профессия и место жительства не восстанавливаются задним числом. Состояние меняется только эффектом истории; жизнь остального населения не симулируется.

Стадия ребёнка вычисляется по возрасту: 0–6 — раннее детство, 7–14 — школьный возраст, 15–25 — юность, от 26 — взрослая жизнь.

## Автономные рубежи друга и sibling (GEN-57)

Друг детства и уже существующий `sibling` могут получить первую известную профессию в назначенном для NPC возрасте 16–22 лет. Профессия одна из четырёх: техник, медик, агроном или координатор. План возраста и профессии вычисляется из seed, ID NPC и версии `npc-autonomy-v1`; годовой tick проверяет только назначенный возраст. Уже известная профессия, смерть, отсутствие человека, ещё не наступившее знакомство или пропущенный возраст не запускают ретроспективное заполнение биографии. Переезд планируется в возрасте NPC 23–35 лет и требует достоверно известного исходного сектора. При неизвестном адресе переезд пропускается; сектор не выводится из имени, роли или сектора героя.

Совершившийся рубеж обновляет `Person.state`, устанавливает один из четырёх защищённых флагов `npcFriendFirstJobAt`, `npcSiblingFirstJobAt`, `npcFriendFirstMoveAt` или `npcSiblingFirstMoveAt` возрастом героя и добавляет одну фактическую запись `life` с годом полёта. Проверка не расходует общий RNG. Рубеж не создаёт память, изменение отношений или дополнительные черты. Переезд друга дополнительно пропускается при текущей или бывшей романтической связи, незавершённой старой романтической линии и в течение пяти лет после другого рубежа; у `sibling` нет романтических ограничений. Автономная первая профессия друга не зависит от романтического статуса.

Сцены «Ведомость смен» и «Свой ритм» открываются только после соответствующего рубежа, пока NPC жив и доступен. Игрок может отказаться от контакта без создания воспоминания; контактный ответ создаёт только указанное текстом воспоминание. Отображение профессии и сектора в карточке человека показывает текущее состояние, а летопись сообщает сам факт изменения. Эти записи доступны через существующий интерфейс; чтение записи не предполагается автоматически.

## Контент

Слоты объявляются в `content/people.json`: уникальный латинский ID из строчных букв и цифр, начинающийся с буквы. Зарезервированные имена и повторы запрещены. Слот `acquaintance` создаёт ID `story-acquaintance`; повторный эффект не создаёт дубль. Имя, грамматический род и сектор выбираются детерминированно по seed и слоту, с учётом уже занятых имён; общий RNG не тратится. Возраст равен возрасту героя в момент знакомства, связь начинается с 45. Начальные роли объявляются в `content/person-roles.json`: сейчас это `colleague`, `friend`, `mentor`; автор может добавить запись без изменения TypeScript.

```json
{ "addPerson": { "slot": "acquaintance", "role": "colleague" } }
```

Имя и род: `{{acquaintance}}`, `{{acquaintance:|а}}`; текущий партнёр разрешается через `{{partner}}`, последний прежний — через `{{formerPartner}}`. Защищайте упоминания присутствием или историческим `exists`/`dead`. Условия и эффекты состояния:

```json
{ "requires": { "person": { "acquaintance": { "availability": "available" } }, "focus": ["relationships"] } }
{ "effects": { "person": { "child": { "sectorId": "bio", "availability": "available" } } } }
{ "requires": { "present": ["child"], "childStage": ["adult"] } }
```

Изменения недоступного, умершего или ещё не известного человека отклоняются до применения других эффектов. Валидатор ограничивает поля и значения, сектор должен существовать; профессия и собственная семья ограничены возрастом. Обычный эффект не меняет `alive`.

```json
{ "relationship": { "action": "start", "person": "acquaintance" } }
{ "cohabit": "hero" }
{ "cohabit": "partner" }
{ "cohabit": "apart" }
{ "relationship": { "action": "end" } }
```

Совместная жизнь у героя перемещает партнёра к герою; жизнь у партнёра использует записанный сектор партнёра. Для старой линии без сведений о секторе сохранён прежний детерминированный расчёт; после такого сюжетного переезда при явной модели этот сектор записывается и другу. Если известный сектор друга совпадает с текущим домом героя, вариант старого события, описывающий переезд в другой сектор, недоступен. При разрыве ID попадает в историю, а совместная жизнь прекращается. При смерти явного партнёра происходит то же сохранение исторической ссылки; отсутствие и смерть не создают нового человека. Семейная поездка использует ID людей, а недоступных для встречи не предлагает.

## Сохранения и детерминизм

Новые поля необязательны, версия базового сохранения остаётся 2. Вычисление старых отношений не меняет сохранение. `repairSave` исправляет ссылку на умершего явного партнёра и сохраняет подтверждённую старую совместную жизнь с умершим другом в истории, прежде чем снять флаг совместной жизни. Ради миграции людей экономика, навыки и воспоминания не меняются. Повторное восстановление идемпотентно. Подстановки, проверки и выбор свойств NPC не используют RNG. При этом добавленный пожилой живой человек участвует в существующем цикле смертности и может изменить последующие случайные числа; полные новые биографии не обязаны совпадать с историческими seed-трассами.

## Ограничения

Слоты объявляются в каталоге заранее; граф связей между NPC, демография, фоновые события и автоматические браки не моделируются. `role` — историческая подпись, а не универсальный граф ролей. Профессия героя и экономика NPC не связаны. Новые истории используют один демонстрационный слот. Для масштабных пакетов понадобятся более широкие данные о повторных отношениях, средства авторской проверки и отдельные фоновые механики.
